## 3. Data quality issues

### 3.1 延賽造成的 `game_sno` 重複

10 個 `game_sno` 在賽程中出現多筆，共多出 11 筆記錄。實際明細：

```
game_sno  15: 04-04 延賽 → 06-27 已完成 (2:9)
game_sno  25: 04-07 延賽 → 05-12 已完成 (1:2)
game_sno  57: 04-24 延賽 → 06-23 已完成 (3:6)
game_sno  80: 05-05 延賽 → 06-26 已完成 (3:1)
game_sno 141: 06-04 延賽 → 06-24 已完成 (3:1)
game_sno 151: 06-09 延賽 → 06-25 保留 (1:4) → 06-28 已完成 (1:4)
game_sno 158: 06-12 延賽 → 06-30 已完成 (5:6)
game_sno 196: 07-10 延賽 → 09-22 未開打
game_sno 200: 07-11 延賽 → 10-03 未開打
game_sno 252: 08-08 延賽 → 10-04 未開打
```

重複群組內的狀態分佈：延賽 10、已完成 7、保留 1、未開打 3。

觀察到的形態（**這是觀察，不是官方規則**）：

- 每個群組都是「一筆 `game_result='1'`（延賽）」加上「一筆改期後的記錄」
- 同群組內的對手與場地完全相同，只有日期不同
- `game_sno` 151 是三筆：延賽 → 保留 → 已完成。保留那筆已經有 1:4 的比分，
  與最終完成的比分相同，看起來是比賽中斷後續行完成
- 相異 `game_sno` 為 **120**，正好是一季例行賽的標準場數

**尚未確認的部分：** 官方沒有說明延賽記錄的正式唯一識別規則，也沒有說明
「保留」與「延賽」在資料上的正式定義。因此本專案目前：

- **保留全部 131 筆**，不刪除、不合併
- 不建立任何「取最後一筆」或「取已完成那筆」的規則
- 使用者若要計算場次相關指標，必須自行決定過濾條件並說明理由

### 3.2 `game_sno` 不應單獨作為 schedule 唯一鍵

上述重複直接證明了這一點：131 筆記錄只有 120 個相異 `game_sno`。

任何以 `game_sno` 為唯一鍵的假設都會出錯，可能的後果包括：

- 用 `game_sno` 建索引或字典會覆蓋掉同 sno 的其他記錄
- 直接 join 會產生重複列，導致場次數、打席數等聚合值被放大
- 「賽程共幾場」這種問題，會因為算 131 或 120 而得到不同答案

目前可行的作法是把 `(game_sno, game_date)` 當成實務上的識別組合
（本次資料中這個組合沒有重複），但這只是本次資料的觀察，**不是已確認的官方規則**。

### 3.3 未完成場次的比分是 0，不是 null

賽程中 44 筆未完成場次（`game_result != '0'`）裡：

- 43 筆比分為 `0:0` — 這是官方的預設值，**不代表真的 0 分**
- 1 筆比分非 0：`game_sno 151`，2026-06-25，狀態「保留」，比分 1:4

風險：若直接對 `home_score` / `visiting_score` 做平均或加總而沒有先過濾，
43 筆假的 0 分會把數字整個拉歪。

處理方式：**原值保留，未做任何修正。** 使用比分前必須先用 `game_result == '0'` 過濾。
沒有把 0 改成 null，因為那會是我們自行加上的解讀。

### 3.4 `batting_average` 是累計值，不是單場值

`batting_average` 來自官網 `Avg`，是該場結束時的累計季打擊率。
若誤當成單場打擊率使用，任何「近期打擊率走勢」的計算都會錯。

單場打擊率需要自己用 `hits / at_bats` 算，並處理 `at_bats == 0` 的情況。
本階段沒有計算任何衍生指標。

### 3.5 其他保留未處理的事項

| 項目 | 狀況 |
| --- | --- |
| `home_pitcher_acnt` / `visiting_pitcher_acnt` | 未開打場次有 Acnt 但姓名為空字串。**語意尚未確認**（是否確為預告先發），本階段只原樣保留，沒有做任何對照或解讀 |
| 場地欄位 | 賽程的 `field` 是簡稱（如「亞太主」「洲際」），與球員逐場資料的 `FieldNo`（`F08` 等）如何對應仍未確認。球員逐場的 `FieldNo` 本次沒有收進 processed data |
| 主客場 | 賽程有 `is_home`，球員逐場資料沒有。要知道某場球員是主場還是客場，必須經由賽程 join，而模糊對接的 7 筆會讓這件事變得不確定 |
| 時區 | 所有時間都沒有時區標記，推定為台灣時間 |
| 其他年份 | 只驗證 2026 年，不確定其他年份結構相同 |
